# v0.15.1 — Browser Tools, Platform Resilience, and Compaction Fixes

2026-06-25

Follow-up to v0.15.0. Adds three new browser/network tools, hardens Telegram
progressive delivery, and fixes `/compact` so it no longer drops the user's
latest directive.

## What's new

### Browser & network tools

- **`browser_get_json`** — Extract embedded `window.*` JSON variables from
  rendered pages. Useful for sites like Indeed that store job results in
  `window.mosaic.providerData` or `window._initialData`.
- **`browser_interact`** — Drive real-browser interactions (fill, click,
  select, press, wait) for JavaScript-heavy forms and filters.
- **`http_get` curl_cffi support** — New `use_curl_cffi` parameter lets the
  model request TLS/HTTP fingerprint impersonation to bypass Cloudflare-style
  bot blocks. Factory-created `http_get` tools keep their existing 403-fallback
  behavior via a new internal flag.
- **`browser_get` / `browser_get_links` `headless` parameter** — Allows the
  agent to request a headed browser session to evade bot detection on sites
  like Indeed and LinkedIn.
- **Shared browser fetch headed mode** — `hestia.tools.browser.fetch.fetch_url`
  now implements `headless=False` by launching a visible Playwright browser,
  and refactors page navigation into `_fetch_in_context` so session persistence
  works for both modes. Also raises the bot-protection threshold so a single
  footer phrase (e.g. "reCAPTCHA") no longer discards a real page.

### Scheduler observability

- **Public `/api/health` endpoint** — returns process liveness and scheduler
  state (`{"status": "ok"/"degraded", "scheduler": {"running": ...}}`).
- **`Scheduler.is_running` property** and startup log line.
- `hestia serve` wires the scheduler into the web context so the health check
  can report whether the background loop is active.
- Auth middleware exempts `/api/health` so external monitors can ping it.

### Telegram reliability

- Streaming callback now skips edits when the text hasn't changed, avoiding
  Telegram's "message is not modified" 400 errors.
- Streaming callback catches send/edit failures and continues, so a transient
  Telegram error doesn't abort the turn and leave a half-finished message.
- Final response falls back to sending a new message if editing the streamed
  message fails.
- `Platform.edit_message` signature now accepts platform-specific kwargs, with
  a Telegram-only `fallback_to_new_message` option.
- Runtime edit-rate limit restored to `1.5s` for snappier updates.

### `/compact` correctness

- Verbatim tail now extends backward to include the most recent user message
  when the fixed window would otherwise cut it off. This prevents a compact
  from losing the current user directive while the agent is mid-turn.
- Compaction system prompt now explicitly instructs the summarizer to
  prioritize the most recent user message/intent over older plans.
- Added regression test for the "long agent turn after user directive" case.

## Upgrade notes

- No schema changes. Restart `hestia-serve.service` after upgrading.
- If you have custom platform adapters that override `edit_message`, update the
  signature to accept `**kwargs`.
