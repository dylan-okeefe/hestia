# v0.15.0 — Trust Boundary, Concurrency, and Memory Lifecycle

2026-06-22

Large release. Closes the two top findings from the v0.13 deep review (a single
enforced trust boundary and a per-session concurrency model) and adds the memory
lifecycle: in-session compaction, session-end fact extraction, and overnight
memory maintenance.

## What's new

### Trust, Concurrency & Persistence
- **Unified `CapabilityGate`** — one trust boundary every tool-execution path
  passes through. Enforces per-user trust, gates the destructive subset on
  unattended channels, and escalates (confirm on attended, deny on unattended)
  when content is injection-flagged.
- **Per-session turn serialization** — one lock per session, plus slot/cache/
  message-sequence race fixes and a scheduler try-acquire skip.
- **Persistence split** — `sessions.py` split into `SessionStore`,
  `MessageStore`, and `TurnStore` with a DTO boundary (deprecated re-export
  facade retained for one release).
- **Blocked-actions digest** — gate denials/escalations are audited and
  delivered as a digest.
- ADR-040 through ADR-049.

### Memory Lifecycle
- **`/compact` meta-command** (CLI, Telegram, Matrix) — compacts the current
  session in place with a task-aware summary, archiving originals.
- **Session-end fact extraction** — durable, structured facts captured at
  archive, with a single summarization shared with the handoff.
- **Overnight memory maintenance** — scheduled dedupe, conservative prune, and
  confidence-gated contradiction supersession, all soft-delete and reversible
  with a trace, operator digest, and undo CLI.
- **Write-time memory sanitizer** — rejects raw turn dumps and tool-call XML at
  the shared store boundary.

### Browser & Tooling
- Browser stream reliability: active-stream banner, URL navigation, resizable
  responsive layout, `requires_headed` persistence, and saner save/health-check
  behavior.
- Chunked `read_artifact` with `start_at`/`length`.
- Marker-only result classifier, browser fetch rate-limiter and pool, and
  `write_file` recovery fixes.

## Upgrade notes
- Several schema additions are applied automatically on startup (soft-delete and
  protected-set columns, maintenance trace table, compaction archive, `correction`
  column, split stores). Back up and verify on a copy of your runtime DB first.
- Run `hestia memory maintenance ensure-tasks` to enable the nightly/weekly
  maintenance passes; undo with `hestia memory maintenance undo <action-id>`.
- The trust gate now enforces per-user trust and injection escalation; review your
  trust config after upgrading.
- `persistence/sessions.py` is a deprecated facade and will be removed in v0.16.0.
