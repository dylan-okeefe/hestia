# v0.16.0 — Allowlist-Only Authorization, Topic-Scoped Memory, and the Audit Remediation

2026-08-24

The largest release since the project began: two and a half months of work
covering allowlist-only tool authorization for unattended workflows
([ADR-052](../adr/ADR-052-allowlist-only-tool-authorization-for-unattended-channels.md)),
topic-scoped long-term memory, a cross-platform command registry, an
external-tool-module extension point, and the remediation of an independent
security audit.

**Three breaking changes.** Workflows must be re-activated once, terminal
commands see a restricted environment, and direct registry callers must pass
a `ToolCallContext`. Step-by-step instructions are in
[`UPGRADE.md`](../../UPGRADE.md).

## What's new

### Allowlist-only workflow authorization

A workflow may now invoke exactly the tools its activated version grants.
Grants are derived from the node graph at save time, shown as a diff on
activation, and enforced at a single registry-level chokepoint that every
tool invocation passes through — including delegation and recovery paths
that previously bypassed gating. Scheduler trust flags are enforced for
real. See [ADR-052](../adr/ADR-052-allowlist-only-tool-authorization-for-unattended-channels.md)
for the decision record.

### Topic-scoped memory

Long-term memories can be organized into user-named topics; conversations
subscribe to topics and their contents feed context automatically. The
nightly maintenance passes (dedupe, prune, supersede) became scope-aware,
respecting topic boundaries and protected-set flags. The web dashboard's
memory management pages were redesigned around this model.

### Command registry, `/commands`, `/tour`

Slash commands across Telegram and Matrix are now registered centrally and
discoverable in-app: `/commands` lists what is available with usage,
`/tour` walks through them interactively. A manual `/compact` command
compacts the current session on demand, with replaced history recoverable
from an archive.

### External tool modules

Private or domain-specific tools can now be added without forking:
`extra_tool_modules` in config names import paths exposing
`register(registry)`. Explicit registration only — no directory scanning,
no autoloading. See [ADR-053](../adr/ADR-053-external-tool-modules.md).

### Smaller additions

Session-end fact extraction proposes notable facts to long-term memory;
`read_artifact` reads large artifacts in chunks; a sanitizer screens memory
writes; capability-gate denials roll up into a reviewable blocked-actions
digest.

## Security

This release ships the remediation of an independent audit of the
codebase. The changelog's Security section lists each change; the headline
is that workflow tool invocations now pass through the capability gate
without exception. Two documents are new or substantially expanded:

- [`SECURITY.md`](../../SECURITY.md) — how to report vulnerabilities via
  GitHub private vulnerability reporting, plus a support policy.
- [`docs/guides/security.md`](../guides/security.md) — the threat model
  and hardening guide: trust and channel classification, deployment
  posture guards, filesystem/terminal boundaries, and best-effort egress
  controls stated as best-effort.

## Upgrading

See [`UPGRADE.md`](../../UPGRADE.md#v0160). In short: back up, pull and
sync, restart — then re-activate each workflow once and confirm its
authorization diff. Migration m011 pre-populates grants from active
versions, so most users will see empty diffs to confirm.
