# Hestia v0.12.0 — Release Notes

**Release date:** 2026-05-19

## Highlights

Hestia v0.12.0 is the largest frontend release since the project began. It ships a complete web dashboard rewrite (14 pages, auth, dark mode, responsive), a visual workflow editor with triggers and execution, a full user registry with role-based access, and a shared CSS component system that replaces ad-hoc styling.

This release also closes the L169–L191 feature arc: ~20 days of work that turned the web UI from a single config page into a full administration interface.

## New Features

### Web Dashboard
- **14-page React SPA** built with Vite — every major subsystem now has a dedicated page.
- **Authentication** — platform-based login via Telegram or Matrix; token-based sessions with automatic expiry.
- **Responsive design** — collapsible mobile sidebar, persistent desktop nav, touch-friendly controls.
- **Dark mode** — respects system preference, manual toggle, CSS custom property tokens.
- **Shared CSS system** — `variables.css`, `utilities.css`, `components.css`; inline styles capped at <20.

### Workflow Editor
- **Visual editor** — React Flow canvas with drag-and-drop nodes and edges.
- **10 trigger types** — manual, schedule (cron), chat command, webhook, message, email, proposal, tool error, workflow completed, session started.
- **7 node types** — Tool Call, LLM Decision, Send Message, HTTP Request, Condition, Investigate, Inference.
- **Variable interpolation** — `{{data.command}}` syntax for passing trigger payload into nodes.
- **Versioning** — save multiple versions, activate one at a time.
- **Test runs** — execute manually and inspect per-node results and outputs.

### User Registry
- **Users, identities, rooms, memberships** — full relational model in SQLite.
- **Role-based access** — `admin` and `user` roles; admin-only routes (Errors, Users) gated server-side.
- **User selection** — when multiple users exist, the login flow lets callers pick their identity.

### Config & Scheduler UI
- **Config search** — live filter across all keys with human-readable descriptions.
- **Trust presets** — visual cards for paranoid / prompt_on_mobile / household / developer with one-click apply.
- **Scheduler management** — create, edit, enable/disable, and trigger cron tasks from the web UI.

## Security

- **Workflow API authorization** — mutation routes (`update`, `delete`, `activate`, `test-run`) enforce ownership or admin role.
- **Scheduler task scoping** — `GET /tasks` returns only the caller's tasks unless the caller is an admin.
- **Webhook HMAC** — per-workflow secrets with SHA-256 HMAC verification and replay-attack protection.
- **Trust system** — `paranoid` (no auto-approval) through `developer` (all tools auto-approved) with shell-pattern blocking.

## Infrastructure

- **FastAPI static serving** — production Vite builds served from `src/hestia/web/static/`.
- **Reusable components** — `Button`, `Toast`, `FormField` with consistent design tokens.
- **Config schema API** — backend exposes field types and enums for rich frontend rendering.

## Breaking Changes

None.

## Upgrade Notes

1. Run Alembic migrations: `hestia db upgrade`
2. Rebuild static assets: `cd web-ui && npm run build`
3. Restart the server to pick up new static files.
4. The first user to log in via the web dashboard becomes the admin automatically.
