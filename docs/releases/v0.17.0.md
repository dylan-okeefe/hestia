# v0.17.0 — Inference Backend Profiles, Coding-Agent Bridge, Telegram Vision, and Error-UX Hardening

2026-11-05

Two months of work since v0.16.1. No breaking changes; the one new table
(`chat_settings`) is created automatically by an idempotent runtime
migration.

## What's new

### Inference backend profiles

Named backend profiles with admission control decouple `hestia serve`
from any specific inference server — including the previously bundled
`hestia-llama` unit, which is now one backend among several
([L232](../../docs/development-process/loops/L232-inference-backend-profiles.md)).

### Telegram coding-agent bridge

A separate `tg-agent` service routes designated Telegram chats to a
sandboxed Pi coding agent instead of the conversational model, with a
reviewer pass before code lands and a deploy pipeline for authorized
requests
([L233](../../docs/development-process/loops/L233-telegram-coding-agent-bridge.md)).

### Telegram vision

Photos sent to the bot are downscaled (≤1024px JPEG, ffmpeg) and passed
to the vision-capable model as `image_url` parts. Images persist in
session history so follow-up turns retain context; compaction archives
drop them. When vision is disabled, the bot replies that it cannot see
images instead of silently dropping the photo
([L234](../../docs/development-process/loops/L234-telegram-vision.md)).

### Guided `/intro`

A narrated first-run walkthrough for new users, complementing `/tour`.

### `/thinking`: per-chat reasoning display

Chats can hide or show the model's 💭 reasoning output with
`/thinking [on|off]`. The setting is stored per chat in a new
`chat_settings` table (schema + idempotent runtime migration) and
survives restarts. Operator chats default to showing reasoning; every
other chat — groups included — defaults to hidden. Both reasoning
display paths (final answer and pre-tool-call) are gated, and a gate
failure falls back to showing rather than failing the turn.

### Reliability and operability

- **Stream-state `KeyError` fix (L249).** A runner callback deleted
  `message_id` from the adapter's shared stream-state dict; the next
  streamed chunk raised `KeyError: 'message_id'` and failed the turn
  mid-tool-loop. Segments are now re-seeded, backed by a regression test
  and an AST scan that fails CI if any code under `src/hestia/platforms/`
  deletes a key from a shared `state` dict.
- **Descriptive unexpected-error messages (L248).** Failures now name the
  exception class and a sanitized detail (paths and URLs collapsed to
  placeholders, 200-char cap, single line) instead of a generic
  "Something went wrong," with a short turn-id reference at the engine
  path for log lookups.
- **Retry-state recovery (#90).** Turns that recovered from a
  thinking-budget abort or transient inference error no longer die on an
  illegal `retrying → executing_tools/done` state transition; recovery
  routes through `awaiting_model`, proven by strict-journal regression
  tests.
- **Coding-agent bridge backends (L251).** Chats on the Telegram
  coding-agent bridge can be switched between the default Pi agent and a
  Kimi Code CLI session with an operator-only `/agent [pi|kimi]`
  command, persisted per chat. Kimi mode runs one persistent CLI session
  per chat in a configured working directory, one message in flight at a
  time.
- Voice pipeline runs on CPU-only hosts; the TTS unit can pin a device.
- Browser automation derives its User-Agent from the installed Chromium.
- Telegram web-auth login codes self-delete after 5 minutes.
- Coder-bot mode logs unrouted allowlisted chat ids for one-message
  onboarding.
