## CRITICAL

### [ ] C1 — Token-count cache collides on tool-call messages (context overflow risk)
- **Location:** `src/hestia/context/builder.py:363` and `:394`; root cause in `src/hestia/core/serialization.py:18-29`
- **Issue:** `_count_tokens`/`_count_body` key the tokenize cache on `(message.role, message.content)` only. But `_render_message` → `message_to_dict` embeds the full `tool_calls` array (incl. `json.dumps(tc.arguments)`). Assistant tool-call messages almost always have `content == ""`, so **every** assistant tool-call message collides on key `("assistant", "")` and returns the first one's token count. The docstring's claim that omitted fields are "constant length" is true for `tool_call_id`/`reasoning_content` but **false** for `tool_calls.arguments` (a 5 KB `write_file` and a no-arg `current_time` hash identically).
- **Impact:** Nondeterministic under/over-counting of the most common message type in an agentic loop. On an 8K context, undercount → builder thinks the prompt fits → llama-server truncates/rejects. This directly violates the budget invariant the whole system exists to enforce.
- **Fix:** Incorporate the tool-call signature into the cache key. Options: (a) key on a hash of the rendered JSON dict; (b) key on `(role, content, tuple((tc.name, hash(arguments_json)) for tc in tool_calls))`; (c) simplest safe fix — bypass the cache entirely when `msg.tool_calls` is set, since those messages rarely repeat verbatim. Apply to both `_count_tokens` and `_count_body`.
- **Tests:** Add a builder test with two assistant messages, same empty content, different tool_calls/args; assert distinct token counts and that total budget accounting reflects the larger payload.

## HIGH

### [ ] H1 — Headless "fail-closed" for `write_file` doesn't exist; runtime runs fully open
- **Location:** `src/hestia/policy/default.py:269-273` (filter), `:216-222` (auto_approve), `config.runtime.py:130-138`
- **Issue:** Documented invariant: "headless (scheduler) → `write_file` and `terminal` always denied (fail closed)." Reality: `filter_tools` scheduler branch only strips `SHELL_EXEC` and `EMAIL_SEND`; it **never** strips `WRITE_LOCAL`. So `write_file` always survives tool-filtering during a scheduler tick, leaving only the confirmation gate — which `auto_approve()` returns `True` for whenever `auto_approve_tools` contains `"*"` or `"write_file"`.
  - `terminal` headless: double-gated (filter + confirm).
  - `write_file` headless: single-gated (confirm only) — weaker and asymmetric.
  - Live deployment (`config.runtime.py`) uses `auto_approve_tools=["*"]`, `scheduler_shell_exec=True`, `scheduler_email_send=True` → scheduled/headless turns can write files, run shell, and send email with **no confirmation, no human**.
- **Impact:** Security/design divergence; latent defense-in-depth hole even for `household` preset. Operator chose `developer` posture, but the advertised guarantee is simply false.
- **Fix:** (1) Add a `scheduler_write_local` trust field (default `False`) and strip `WRITE_LOCAL` in the scheduler branch symmetric with `scheduler_shell_exec`, so `write_file` is double-gated like `terminal`. (2) Update ADR/docs: headless fail-closed is **preset-dependent**, not absolute. (3) Decide whether `auto_approve_tools=["*"]` should bypass confirmation *during a scheduler tick* at all (recommend: no).
- **Tests:** Scheduler-tick integration test asserting `write_file`/`terminal` are denied under `paranoid` and `prompt_on_mobile`, and explicitly allowed (documented) under `household`/`developer`.

### [ ] H2 — `curl_cffi` fallback bypasses IP-based SSRF protection on redirects
- **Location:** `src/hestia/tools/builtin/http_get.py:121-165` (fallback), `:75-97` (`_is_url_safe`)
- **Issue:** Primary path uses `SSRFSafeTransport` (resolves + checks IP at connect time — good). The `curl_cffi` fallback can't use a custom transport and validates redirects only via `_is_url_safe`, which checks scheme/hostname **presence** but does **no DNS resolution and no IP-range check**. A malicious external endpoint returning `403` then `302 → http://169.254.169.254/` (cloud metadata) or `http://localhost/` passes the check and gets fetched.
- **Impact:** SSRF to internal/metadata endpoints. Gated behind `use_curl_cffi_fallback=True` (default off) + an initial 403, so conditional — but enabling the flag opens it.
- **Fix:** In the `curl_cffi` redirect loop, resolve the redirect target and run it through the same `_BLOCKED_RANGES` check as `SSRFSafeTransport`. Factor the resolve+check into a shared helper (e.g. `_assert_ip_allowed(hostname)`) used by both the transport and the fallback.
- **Tests:** curl_cffi fallback redirecting to a private/loopback/IPv6-loopback target → blocked.

### [ ] H3 — Frontend mutation helpers ignore `res.ok` (silent failures)
- **Location:** `web-ui/src/api/client.ts:100-117, 126-129, 164-165, 201-206`
- **Callers:** `web-ui/src/pages/Proposals.tsx:51-55`, `web-ui/src/pages/StyleProfile.tsx:48-55`, `web-ui/src/pages/Scheduler.tsx:106-109`
- **Issue:** `acceptProposal`, `rejectProposal`, `deferProposal`, `deleteStyleMetric`, `runTaskNow`, `saveConfig` resolve without checking `response.ok`. On 401/403/500 the promise still resolves; UI refreshes and reports success for actions the backend rejected.
- **Impact:** Operator believes a proposal accept/reject or "run now" happened when it didn't.
- **Fix:** Add a `checkOk(res)` helper (or centralize in `apiFetch`) that throws on `!res.ok`; apply to all mutating endpoints, matching the already-correct read helpers (`fetchProposals`, `createTask`).

## MEDIUM

### [ ] M1 — Streaming vs non-streaming disagree on malformed tool args
- **Location:** `src/hestia/orchestrator/execution.py:342-346` vs `src/hestia/core/inference.py:443-448`
- **Issue:** Non-dict tool-call `arguments`: non-streaming **skips** the call (model retries next iteration); streaming **raises** `InferenceServerError` (fails the whole turn). Same garbage output, different outcome based on stream flag.
- **Impact:** Streaming sessions waste turns on a failure mode non-streaming recovers from — and quantized models emit non-dict args regularly.
- **Fix:** Make streaming match `chat()`: log a warning and skip the malformed call instead of raising.

### [ ] M2 — `egress_audit_enabled` config flag is dead code
- **Location:** `src/hestia/config.py:352`; `src/hestia/tools/builtin/http_get.py:256-278`; also `web_search` egress; never read in `app.py`
- **Issue:** `SecurityConfig.egress_audit_enabled` is documented (ADR-017) as the audit on/off switch, but `_record_egress` logs unconditionally when a trace store + session id exist. Setting it `False` does nothing.
- **Fix:** Honor the flag in `_record_egress` (both http_get and web_search), or remove the flag and update ADR-017. Prefer honoring it.

### [ ] M3 — Webhook: `endpoint is None` matches all paths; no replay protection; header leak
- **Location:** `src/hestia/web/routes/webhooks.py:33-37, 42-57, 76`
- **Issues:**
  1. A workflow with no `endpoint` in `trigger_config` matches **any** `/webhooks/{endpoint}` path (`... or wf.trigger_config.get("endpoint") is None`). Its secret is tried for every webhook URL.
  2. HMAC is computed over the body only — no timestamp/nonce → captured requests are replayable indefinitely.
  3. `dict(request.headers)` (incl. `X-Webhook-Signature`) is published into the event payload → flows into workflow variables/logs.
- **Fix:** (1) Drop the `is None` wildcard or make it explicit opt-in. (2) Add a signed timestamp + short replay window, or a nonce cache. (3) Strip the signature header (and any auth headers) before publishing.
- **Note:** secret-less webhook workflows are currently un-triggerable (empty `secrets_list` → always 401). Fail-closed, but document or fix as a usability decision.

### [ ] M4 — Dashboard auth code can be delivered to a shared Matrix room
- **Location:** `src/hestia/web/auth.py:84-107`
- **Issue:** `_get_configured_user` uses `allowed_rooms[0]` for Matrix; the one-time login code is `send_message`'d there. Any room member sees the code and can complete login — defeats ADR-034 2FA in a multi-occupant room.
- **Fix:** For Matrix, deliver codes to a specific user identity via a direct channel, not a shared room; or document that Matrix dashboard auth requires a single-occupant room.

### [ ] M5 — Memory search has a fail-open cross-user branch
- **Location:** `src/hestia/memory/store.py:332-337, 350-355`
- **Issue:** When `platform`/`platform_user` resolve to `None`, the query drops the scope filter and returns **all users'** memories. Safe inside `process_turn` (contextvars set), but any caller without runtime context leaks across users — wrong default for multi-user (ADR-038).
- **Fix:** When scope can't be resolved, return empty or raise rather than running unscoped. Require explicit `platform_user` for any intentional cross-user listing (admin path).

### [ ] M6 — `IllegalTransitionError` exits turn with no user notice / no FAILED state
- **Location:** `src/hestia/orchestrator/engine.py:237-238`; `src/hestia/orchestrator/finalization.py:92-149`
- **Issue:** Engine re-raises `IllegalTransitionError` instead of routing through `handle_unexpected_error`. `finally` runs `finalize_turn`, which doesn't set `FAILED` or message the user (records trace outcome `"partial"`, leaves state non-terminal until `recover_stale_turns`). User sees nothing; exception hits the platform adapter.
- **Fix:** Treat illegal transitions as internal failure: force-transition to `FAILED` and send the sanitized user error, consistent with other exception handling.

### [ ] M7 — `print()` used for warnings in inference hot path
- **Location:** `src/hestia/core/inference.py:441, 444`
- **Issue:** Malformed tool-call warnings use `print()`, bypassing `logging_config` (no level control, stdout only).
- **Fix:** Replace with `logger.warning(...)`.

### [ ] M8 — `AuthManager` leaks expired pending codes (and sessions)
- **Location:** `src/hestia/web/auth.py:109-123`
- **Issue:** `_cleanup_stale_entries` prunes `_rate_limits` and `_code_request_limits` but **not** `_pending_codes`. Expired codes persist until that exact code is submitted. Expired `_sessions` only removed on access. Unbounded growth in a long-running daemon.
- **Fix:** Prune `_pending_codes` by `expires_at` in `_cleanup_stale_entries`; optionally sweep expired `_sessions` too.

### [ ] M9 — Test gaps on highest-risk paths
- **Locations / gaps:**
  - `src/hestia/core/inference.py:420-497` — `chat()` (malformed-output defense) has **zero** direct tests; only `chat_stream` covered (`tests/unit/test_inference_client.py`). Add: empty `choices`, malformed JSON args, non-dict args, `call_tool` unwrap, XML `<tool_call>` fallback.
  - `src/hestia/orchestrator/execution.py:91-193` (`MaxIterationsError`) and `:402-420` (per-turn tool-call cap) — **no behavioral tests**. Add canned `ChatResponse` sequences to `tests/unit/orchestrator/test_execution.py`.
  - `src/hestia/tools/builtin/http_get.py:35-37` — IPv6 blocked ranges have **no tests**; `tests/unit/workflows/nodes/test_http_request_node.py:36-38` mocks `_is_url_safe` away instead of exercising real blocking. Add IPv6 + workflow-node real-SSRF cases.
  - `src/hestia/policy/default.py:191` `tool_result_max_chars()` is tested but **never called in production** (no consumer in `src/hestia/`). Wire truncation into orchestrator tool-result handling **and** test a 50 KB result is clipped before re-prompting (also a context-budget protection).
- **Mock hygiene:** standardize a `ChatResponse` factory in `tests/conftest.py`; stop using `MagicMock` for inference responses (`tests/unit/test_injection_orchestrator.py:67-74`).

### [ ] M10 — Frontend failure-mode bugs
- **Locations / issues:**
  - `web-ui/src/hooks/useCurrentUser.ts:31-35` (+ `web-ui/src/context/AuthContext.tsx:43-51`): when `auth_enabled=false`, `authenticated:true` but `userId:null`; hook refuses to load → Profile/Knowledge/StyleProfile show error states on local/dev installs. Fix: skip userId requirement when auth disabled (or populate a default system user id).
  - `web-ui/src/hooks/useWorkflowEditor.ts:106-134` + `web-ui/src/pages/WorkflowEditor.tsx:106-167`: on load failure, editor renders an editable empty canvas with active save → can overwrite an existing workflow with an empty graph (data-loss). Fix: render error/retry state; disable save until a successful load.
  - `web-ui/src/pages/Profile.tsx:140`, `web-ui/src/pages/Knowledge.tsx:119`: redirect to `/login`, but `App.tsx` has no `/login` route → NotFound. Fix: call `logout()` / navigate to root.
  - Mutation handlers lacking try/catch + user feedback: `AdminUsers.tsx:90-139`, `Scheduler.tsx:84-109`, `ErrorDashboard.tsx:72-87`. Fix: wrap in try/catch, surface error toast.

## LOW

### [ ] L1 — Handoff messages identified by string prefix
- **Location:** `src/hestia/context/builder.py:252`
- **Issue:** Any user message starting with `"[Previous session context]"` is treated as protected handoff; user can spoof to pin their message into protected context.
- **Fix:** Use a structured flag on `Message` instead of content sniffing.

### [ ] L2 — Terminal blocked-pattern rails are weak (documented as non-boundary)
- **Location:** `src/hestia/tools/builtin/terminal.py:18-24`
- **Issue:** e.g. `rm -rf /etc` doesn't match the `rm -rf /` pattern. Documented as defense-in-depth, not a boundary — fine to keep, just don't represent as protection.
- **Fix (optional):** tighten patterns or drop the pretense; the real control is confirmation/trust.

### [ ] L3 — Injection scanner bypassable by construction
- **Location:** `src/hestia/security/injection.py:51-81, 96-100`
- **Issue:** Entropy scan skipped for "structured" content → payload hidden in JSON/base64 dodges detection; small pattern list (no "disregard the above", translations, homoglyphs). Non-blocking (annotate-only), so acceptable as defense-in-depth — but the guide oversells it.

### [ ] L4 — Unguarded dict access in inference tool-call parsing

- **Issue:** `choice["message"]`, `tc["function"]`, `fn["arguments"]`, `fn["name"]`, `tc["id"]` raise `KeyError` if the server/model omits a field → wasted turn (caught only by generic handler).

### [ ] L5 — Frontend admin route reachable by URL; query fires before role check

## Positive observations (do NOT regress)
- Turn boundary safety net (`engine.py:203-256`): contextvars set/reset in `finally`; `ContextTooLargeError` + generic errors funnel through finalization; `finalize_turn` always runs; user-facing error sanitization separates `HestiaError` from internal leakage.
- `SSRFSafeTransport` resolves + validates at connect time (defeats redirect SSRF on primary path) and is honest about residual DNS-rebinding TOCTOU.
- Rate limiting precedes context mutation in `process_turn`; circuit breaker for repeated empty-arg tool failures (`execution.py:481-500`) and reasoning-without-action guardrail (`:119-131`) are exactly the right small-model compensations.
- Memory store: parameterized SQL throughout + FTS5-syntax sanitization + per-user scoping.
- Policy/trust layering: per-user overrides, capability-set gating, semantic `is_paranoid()`.
- CSS discipline holds (11 inline styles vs 20 cap; remainder genuinely dynamic).
- Slot-manager LRU well covered (rollback on corrupt restore, filename sanitization, basename-only DB paths).
