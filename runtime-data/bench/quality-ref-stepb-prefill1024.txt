The orchestrator chooses which agent responds by first interpreting the resident’s message and identifying the task type, such as a reminder, schedule update, household coordination, or general question. It then checks the relevant context: short-term memory for recent conversation, long-term facts for stable household information, and the schedule of obligations for active commitments. Based on that context, it selects the agent whose responsibilities best match the request, while also considering confidence, urgency, and whether another agent has already handled part of the task.

If the request is ambiguous or spans multiple domains, the orchestrator may route it to a primary agent and allow supporting agents to contribute context or confirm details. For example, a message about “the dinner tomorrow” might involve the schedule agent for timing, the household agent for preparation tasks, and the memory agent for preferences or past notes. The goal is to avoid duplicate or conflicting responses by making one agent responsible for the final reply, while still using the most relevant information.

Reliability is emphasized over cleverness because household assistance depends on trust and consistency. A resident needs to know that reminders, appointments, and obligations will be handled predictably, not creatively. A clever response that sounds helpful but misses a scheduled task, changes a commitment, or invents a detail can cause real problems, such as a missed appointment or an unprepared household task.
