The orchestrator chooses which agent responds by interpreting the resident’s message and matching it to the agent whose responsibilities and context are most relevant. If the message concerns a scheduled obligation, the scheduling or reminder agent is likely selected; if it depends on remembered household facts, the long-term memory agent is consulted; if it requires continuity from recent conversation, short-term memory is used. The orchestrator therefore acts as a routing layer, gathering the appropriate context before generating a reply.

It also considers what information is needed to answer safely and accurately. Rather than letting one agent guess from incomplete context, the orchestrator can combine short-term memory, long-term facts, and the schedule of obligations. This helps ensure that the response reflects the household’s actual state, such as whether a task is already scheduled, whether a resident has a known preference, or whether a recent conversation changes the meaning of the request.

Reliability is emphasized over cleverness because household assistance depends on dependable behavior. A missed reminder, wrong appointment, or forgotten obligation can have real consequences, while a slightly less elegant answer is usually acceptable. The system should prioritize correctness, consistency, and predictable handling of tasks over producing a more creative or impressive response.

In this setting, “cleverness” can introduce uncertainty: an agent might infer something plausible but wrong, or choose a response that sounds helpful while failing to act on the actual obligation. Reliability means the assistant should be conservative, context-aware, and accountable to the household’s schedule and facts, so residents can trust it to support daily life without surprises.
