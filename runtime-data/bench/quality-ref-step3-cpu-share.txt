The orchestrator chooses which agent responds by interpreting the resident’s message and matching it to the agent whose responsibilities and context are most relevant. It considers the type of request—such as a household task, a reminder, a factual question, or a scheduling need—and then selects the agent that maintains the appropriate memory or obligation schedule. For example, an agent tracking appointments or household duties would be preferred for a reminder, while an agent holding long-term facts would be used for a stable household detail.

After selecting the agent, the orchestrator gathers the relevant context before generating a reply. This context may include short-term memory from recent interactions, long-term facts about the household, and scheduled obligations that affect the answer. By assembling this information, the assistant can respond in a way that is consistent with prior conversations and current household needs, rather than answering from an isolated or incomplete view.

Reliability is emphasized over cleverness because household assistance depends on dependable behavior. A missed reminder, incorrect task assignment, or inconsistent answer can cause real inconvenience, while a simple but correct response is usually safer and more useful. In this setting, the assistant’s value comes from consistently doing the right thing at the right time, not from producing impressive or creative replies.

This reliability-first approach also supports trust. Residents are more likely to rely on the assistant if it behaves predictably, remembers important obligations, and avoids unnecessary complexity. A plain, accurate reminder is preferable to a clever response that risks misunderstanding the request or failing to act on it.
