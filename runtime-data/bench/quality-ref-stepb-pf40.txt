The orchestrator chooses which agent responds by first interpreting the resident’s message and identifying the task type, such as a reminder, scheduling request, household chore, or factual question. It then checks the relevant context: short-term memory for recent conversation, long-term facts for stable household information, and the schedule of obligations for time-sensitive commitments. Based on that context, it routes the request to the agent whose responsibilities and memory best match the task.

If multiple agents could respond, the orchestrator prefers the one with the clearest match to the request and the most reliable access to the needed information. For example, a reminder about an appointment should go to the scheduling or reminder agent, while a question about a household preference may go to the memory or facts agent. If the intent is ambiguous, the orchestrator may use a conservative fallback, ask for clarification, or choose the agent least likely to miss an obligation.

Reliability is emphasized over cleverness because household assistance involves commitments that affect people’s daily lives. A missed reminder, wrong appointment time, or forgotten chore can cause real inconvenience, even if the assistant’s response sounds impressive. The system should therefore favor predictable routing, explicit confirmation, and safe handling of uncertain requests rather than speculative or overly creative behavior.

In short, the orchestrator acts as a careful dispatcher: it matches the message to the right agent using memory, facts, and schedule context, then chooses the safest response path.
