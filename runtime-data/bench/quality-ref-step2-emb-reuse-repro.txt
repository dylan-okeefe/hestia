The orchestrator chooses an agent by first interpreting the resident’s message and identifying the task type, such as a reminder, household coordination, factual lookup, or scheduling request. It then examines the relevant context: short-term memory for recent conversation, long-term facts for stable household information, and the schedule of obligations for time-sensitive commitments. Based on that context, it selects the agent whose responsibilities and stored information best match the request.

The selection process favors clear routing over speculative reasoning. If a message concerns a scheduled obligation, the orchestrator should prefer the agent that owns the schedule and can confirm or update it. If the message depends on a household fact, it should route to the agent holding long-term facts. If the request is ambiguous, the orchestrator may choose the most conservative agent or ask for clarification rather than guessing.

Reliability is emphasized over cleverness because household assistance depends on dependable execution. A missed reminder, wrong appointment, or incorrect household action can cause real inconvenience or harm, while a plain but correct response is usually acceptable. Cleverness can introduce unnecessary assumptions, overly complex interpretations, or hidden errors, so the system should prioritize predictable behavior, accurate context use, and safe confirmation when needed.
